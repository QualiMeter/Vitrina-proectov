## Проверка интерфейса

Из `frontend/`: `npm ci`, затем `npm run dev`. Открыть `/company/cases` и
нажать «Открыть демонстрацию». Это не вход и не получение прав.
Селектор сценария позволяет проверить пустой список, ошибку и запрет доступа.
Создать черновик, сохранить, вернуться к списку и повторно открыть.
Пустой лимит — null, ноль — отсутствие мест. Формат BOTH сохраняет два независимых лимита.
После перезагрузки созданный ID недоступен: данные были только в памяти.

Справочники и их UUID — демонстрационные; реальные названия/ID получать из
`referenceDataListPublic`. Фильтр статуса локальный: `casesListCompany` пока
не описывает серверный status query. Mocks содержат весь маленький набор;
при интеграции нужна серверная пагинация, нельзя фильтровать только текущую страницу.

## Подключение API

Заменить CompanyCasesRepository адаптером существующего API-клиента:
`casesListCompany`, `casesGetPrivate`, `casesCreateDraft`, `casesUpdateDraft`.
POST содержит только title; остальные поля идут через PATCH с expectedVersion.
Перед записью — CSRF, cookie и обработка 401/403/409/422 по общему клиенту.
Компания и членство должны приходить из реальной сессии, не из demoCompanyId.
Сервер проверяет компанию и объектные права независимо от интерфейса.
contracts.ts — типизированная проекция поддержанных полей, не полный generated API.
При общем codegen заменить её согласованными DTO без повторного ручного enum.
Демонстрационные edit/submit-moderation/open-registration не являются
утверждёнными строками серверного allowedActions.

После #9 расширить его CasePublicDetails публичными полями maxAdmittedSolo и
resultRightsTerms и вставить CaseParticipationConditions в существующую страницу.
Заменить прежний CTA, чтобы не было двух кнопок заявки. Не передавать приватный
CaseDraft в публичный экран; защищённые материалы не загружать.
