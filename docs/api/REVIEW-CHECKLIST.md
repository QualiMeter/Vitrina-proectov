# Проверка единого OpenAPI 0.1.4-draft перед PR

**Цель:** review единого API для Auth / Companies / Cases / Teams / Applications / Stages / Checkpoints / Execution / Submissions / Files / NDA. Ветки фронтенда не требуют переписывания. Это не готовый backend.

## Уже проверено программно

- [x] `openapi.yaml` корректно разбирается как YAML.
- [x] Все локальные `$ref` разрешаются.
- [x] `operationId` уникальны; для всех 75 HTTP-операций на этапе 0.1.2; 85 после добавления итогов есть 2xx-ответ и описание security.
- [x] Имена path-параметров соответствуют шаблонам URL.
- [x] Для POST/PATCH указан обязательный `X-CSRF-Token`.
- [x] Проверены примеры JSON Schema: SOLO/TEAM, required `teamId`, обязательность `reason` при `REJECT`, обязательность `expectedVersion`, запрет клиентского изменения `coverLetterRequired`.
- [x] Первоначальные Auth/Companies endpoints, схемы и параметры совпадают с ранее согласованным YAML.

**Граница проверки:** полный независимый OpenAPI-валидатор, реализация на ASP.NET Core, интеграционные тесты и проверка соответствия исходному ТЗ v5.1 пока не выполнялись.

## Публикация

1. Создать feature-ветку от `main`, например `docs/openapi-v0.1-cases`.
2. Скопировать файлы из ZIP в **корень репозитория**, сохраняя `docs/...`.
3. Создать PR **в `main`** с ответственными backend + FE A/B/C + TL. Не выполнять прямой push в `main`.
4. После review и успешных проверок объединить PR. Изменения функциональности frontend в этой задаче не нужны.

Рекомендуемая следующая часть контракта: `Stages / Checkpoints / Submissions / Files`, включая закрытые материалы и ручной отбор, поскольку без них нельзя подтвердить сквозной P0-сценарий дня 4–5.
