## Как посмотреть

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес Vite и добавьте `/demo/student`. Это отдельная демонстрация с учебными данными в памяти: обновление страницы сбрасывает изменения. `/demo/student/profile` — редактирование; `/demo/student/participations` — участия. Публичный профиль открывается ссылкой внизу формы.

Реальный кабинет — `/student`, профиль — `/student/profile`, участия — `/student/participations`, публичная карточка — `/students/:id`. Неуспешные запросы реального API не заменяются демо-данными.

## Техническая интеграция

- Работа ведётся в существующем `frontend/`, с его UI kit и дизайн-токенами. Из существующего кода изменено только подключение дополнительных маршрутов; общий API-клиент и главная не переписаны.
- `StudentGateway` содержит только API первого дня. Используются существующий `apiRequest`, `VITE_API_BASE_URL`, cookie и свежий CSRF перед изменением профиля. JSON-запрос передаёт `expectedVersion`; конфликт 409 не перезаписывает профиль автоматически.
- Общая same-origin политика сохранена. Cross-origin требует решения FE-C/DevOps и централизованной настройки клиента.
- Токены, профиль и учебные данные не записываются в localStorage/sessionStorage. Сессия проверяется при открытии кабинета и переходах; при возвращении фокуса проверяется в фоне, не сбрасывая редактируемую форму при неизменных правах.
- Для FE-C: после появления общего AuthProvider заменить чтение `/auth/me` в границе кабинета на его согласованный интерфейс. Права на реальные объекты проверяет сервер.
- Для FE-A: импортировать `StudentProjectsBlock` из `src/features/student/StudentProjectsBlock.tsx`, передать только публичные карточки. Компонент дополнительно исключает DRAFT/HIDDEN; не запрашивает вымышленные endpoints. Его модель отображения предварительная, поскольку контракта инициатив ещё нет.
- `contracts.ts` содержит только нужные первому дню схемы и их зависимости из OpenAPI 0.1.5-draft. Генерация: `python3 scripts/generate_student_types.py` с PyYAML. TypeScript-типы не заменяют серверную JSON Schema-валидацию.
- Лимиты обработки аватара уточняются с backend. Клиент использует предусмотренные OpenAPI операции; в демонстрации загрузка отключена и объяснена. Публичное изображение берётся только из предусмотренного API-маршрута, не по произвольному URL из DTO.

## Исправления после review

Для института согласована семантика PATCH: UUID задаёт значение, null очищает его, отсутствие поля сохраняет прежнее. «Не указан» отправляет явный null; неизменённое поле не отправляется. DTO запроса и приватного ответа допускают null. Очистка курса не изменялась: установленный курс остаётся обязательным. Backend должен реализовать согласованную семантику; на реальном сервере она ещё не проверена. При 401 показывается безопасное сообщение и переход на главную вместо отсутствующего /login.

Изменения внесены отдельными коммитами без переписывания существующей истории. Автоматический CI исходного PR прошёл; это не заменяет реальную интеграцию backend и визуальную проверку.

## Генерация типов и контроль расхождений

Для генератора нужен Python 3 и PyYAML. Установка в отдельном окружении: `python3 -m venv .venv-codegen`, затем `.venv-codegen/bin/pip install -r scripts/requirements-codegen.txt`. Генерация: `.venv-codegen/bin/python scripts/generate_student_types.py`. Read-only проверка: `.venv-codegen/bin/python scripts/generate_student_types.py --check`. Версия PyYAML зафиксирована. Quality-job CI выполняет drift-check, а Playwright сохраняет изображения интерфейса 375/1280 px в артефакте frontend-playwright-report. Скриншоты относятся к демо CI-сборки; проверка конфигурации реального Preview и backend остаётся отдельной задачей.

После review страницы разделены по отдельным модулям. Редактор аватара показывает текущее изображение и локальное превью, отзывает object URL и выводит статус рядом с формой. Изменение аватара блокируется при несохранённых полях профиля, чтобы их не сбросить.

## Визуальная система и форматирование

StudentRoot ограничен студенческой навигацией и границей доступа. Текущий общий AppShell поддерживает только university/mentor/admin, содержит заглушку выбора кабинета и служебные разделы; механическое использование его меню для student создаёт неверные переходы. Поэтому каркас студента пока отдельный, при этом используются общие Brand, Button/ButtonLink, Input, Card, LoadingState/EmptyState/ErrorState, шрифт и переменные tokens.css. Новая палитра или второй UI kit не вводятся. После появления общего AuthProvider можно вынести общий responsive shell без изменения бизнес-компонентов.

Для команды предложен Prettier 3.6.2 с едиными настройками после согласования. В этой поставке formatter применялся только к моим студенческим модулям и тестам; несвязанные файлы и зависимости других участников не переформатировались. Версия Playwright не менялась.

CI-снимки покрывают кабинет, редактор, публичную карточку и участия при 375/1280 px; дополнительно меню с keyboard navigation, загрузку, пустой список и 403. Это реальные снимки браузера CI с демонстрационными данными, а не подтверждение работающего backend. Артефакт frontend-playwright-report содержит оригинальные PNG. Отдельно требуется проверка Preview с согласованной конфигурацией авторизации.


## Доработка UI/UX кабинета

Компактная шапка переиспользует Brand и общий UI kit; на телефоне остаются логотип и кнопка меню. Escape закрывает меню и возвращает фокус; текущий раздел выделен, заглушки отмечены «Скоро». Демо-полоса показывает короткую подпись, пояснение раскрывается отдельно.

Обзор содержит активные кейсы, черновики, ожидающие приглашения и сроки подачи. Число всех участий берётся из total; счётчики статусов относятся к загруженной первой странице. Приглашения и сроки загружаются через существующие OpenAPI endpoints: inbox (первая страница 20) и публичные детали первых шести открытых кейсов. Ошибка дополнительного блока не скрывает основную сводку. Для демо используются учебные примеры; в ветке второго дня решения по приглашениям отражаются в сводке. Новые серверные маршруты не вводятся.

Профиль разделён на личные данные и раскрывающиеся секции; панель сохранения закреплена над полями, ошибки скрытых полей раскрывают нужную секцию. Несохранённые правки блокируют переходы маршрутизатора и вызывают предупреждение при закрытии вкладки. Диалог предлагает остаться или явно отказаться от правок; после сохранения блокировка снимается.

В списке участий total подписан как число участий. Пагинация показывает «Страница X из Y» по server pageSize и скрывается при одной странице. Бейджи и действия увеличены. UI-проверки покрывают 320/360/375/400 px, раскрытое меню, Escape, клавиатурный фокус, длинное название без пробелов и горизонтальный скролл; снимки сохраняются в CI.
