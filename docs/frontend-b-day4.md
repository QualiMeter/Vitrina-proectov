# Frontend B четвёртый день

Портфолио и публичные инициативы FB-19–FB-24. Интерфейсы используют общий UI kit, токены, меню, защиту маршрутов и плашку «UI Ready · демонстрационные данные». Предварительные модели выделены в publications/models.ts; они не объявляются утверждёнными серверными DTO.

| Задача | Результат |
|---|---|
| FB-19 | Четыре отдельных раздела: готовые работы, собственные активные инициативы, подтверждённые кейсы и безопасное описание участия в закрытых проектах |
| FB-20 | Форма работы: все девять категорий, результат, личный вклад, описание, технологии, направление, дата, соавторы, необязательные ссылки, изображения и материалы |
| FB-21 | Черновики, редактирование, замечания модерации, отправка на проверку и скрытие опубликованной работы; у работы нет набора команды и контрольных точек |
| FB-22 | Публичный каталог: поиск, категория, технология, направление, статус разработки и интересы; фильтрация полного набора до пагинации, page/pageSize/total из ответа адаптера |

| FB-24 | Создание/редактирование проекта, независимый статус разработки, проблема и цели, вакансии, шесть признаков поиска, публичный контакт и отправка на модерацию |

Статус — UI Ready на типизированных примерах. В OpenAPI текущей ветки отсутствуют PortfolioWork и StudentInitiativeProject, поэтому рабочие маршруты используют явный blocked-адаптер без HTTP-запросов и без автоматической подмены демо. Нужны согласованные BE-22/BE-23 и сквозные DTO BE-32. Новые endpoints не выдуманы. Контракт и генератор типов прежних модулей не изменены.

## Просмотр

- `/demo/student/portfolio` — личное портфолио и список работ.
- `/demo/student/portfolio/new` — добавление работы.
- `/demo/student/projects` — минимальный список для перехода к созданию/редактированию инициатив; полный кабинет автора относится к дню 5.
- `/demo/student/projects/new` — создание проекта.
- `/demo/student-projects` — публичный каталог.
- `/demo/student-projects/00000000-0000-4000-8000-000000000020` — полная карточка.
- `/demo/students/00000000-0000-4000-8000-000000000001/portfolio` — публичное портфолио.

Рабочие аналоги доступны без префикса `/demo`, но новый модуль пока показывает недоступность, а не учебные записи. Приватные страницы остаются за существующей границей сессии; отдельного входа нет. Обновление страницы сбрасывает учебные изменения. Начальный каталог содержит девять опубликованных инициатив и отдельные непубличные примеры для проверки доступа.

## Правила данных

Источник требований — ТЗ v5.1, PW-01–PW-04, SIP-01–SIP-13 и PORT-10–PORT-12. Категории сохранены полностью: учебная работа, курсовая, ВКР, работа с хакатона, pet-проект, стартап, НИР, проект студенческой команды, open-source. Внутренние значения enum пока являются только ключами UI, не контрактом сервера.

Работа не получает статус «Подтверждено компанией» из пользовательской формы. Подтверждённые кейсы — отдельная неизменяемая проекция. Для закрытого продуктового проекта показываются только факт участия и разрешённый период: без названия, внутренних инструкций, роли, репозитория и закрытых материалов. Публичные проекции формируются по белому списку и исключают черновики, замечания модерации и служебные данные.

Модерация и разработка инициативы независимы. Выбор COMPLETED или RECRUITING не публикует запись. Отправка переводит только в PENDING_MODERATION; автор не может сам одобрить публикацию. Сохранение контентных изменений опубликованной записи в учебной модели консервативно снимает публичность и требует повторной проверки. Матрицу полей и поведение публичной предыдущей редакции должен утвердить backend-владелец; UI не предполагает, что любая правка мгновенно становится публичной.

Черновик можно сохранить незавершённым; перед модерацией проверяются обязательные поля. Для готовой работы обязательны название, категория, результат и личный вклад. Репозиторий и сайт необязательны для обоих типов публикаций. Соавторы работы — текстовая подпись, а не команда с правами. Вакансии проекта отделены от фактического состава команды и от признака «Ищу команду».

Публичный контакт вводится отдельно, только как добровольно публикуемая ссылка HTTP/HTTPS. Частный email или телефон профиля не подставляется. Внешняя связь не создаёт заявку и не меняет состав. Настоящая подача заявки и решения автора — FB-27 пятого дня, поэтому кнопка пока явно отмечена «Скоро».

## Формы и вложения

Формы разбиты на смысловые секции; панель сохранения закреплена над полями. Несохранённые изменения защищены диалогом навигации и beforeunload. После сетевой ошибки текст остаётся в форме и доступен повторный save. После 409 сравниваются исходные, локальные и актуальные данные: изменения только на сервере сохраняются, перекрывающиеся поля требуют явного подтверждения. Применение сравнения не отправляет запрос автоматически.

Учебные загрузки хранят File/Blob только в памяти. Изображения имеют предпросмотр; временные object URL освобождаются при удалении/уходе. Для примера допустимы PNG/JPEG/WebP и материалы PDF/ZIP/TXT до 10 МБ — это не согласованные ограничения production. В рабочем модуле загрузка заблокирована до определения upload scope, лимитов, проверки содержимого, прав чтения и lifecycle медиа в BE-32. Ни публичные storage URL, ни локальное постоянное хранилище не введены.

## Границы четвёртого дня

Не реализуются управление членством, принятие/отклонение заявок, передача авторства, назначение куратора, избранное и уведомления. Минимальный список «Мои проекты» нужен для навигации к формам FB-24; он не считается завершением FB-25–FB-30. Общая HomePage, маршрутизатор приложения и API-клиент не переписаны.

## Проверки

```bash
cd frontend
npm ci
npm run lint
npm run typecheck
npm run test:coverage
npm run build
npm run test:e2e
```

Также: `python3 scripts/generate_student_types.py --check`.

Проверяются девять категорий, приватность по прямому URL, проекция публичного портфолио, непротиворечивые статусы, полный поиск до пагинации, отсутствие вымышленных HTTP-вызовов, защита черновика, retry после сети, явное разрешение 409 и загрузки. E2E покрывает создание/модерацию, поиск и фильтры, переход в карточку, отсутствие горизонтального скролла, меню/клавиатуру и ширины 320/375/768/1280/1920 px. Снимки шести основных экранов на 320 и 1280 px сохраняются в артефакте `frontend-playwright-report`, `test-results/screenshots/day4-*`.
