## Проверка интерфейса

`/demo/student` → «Открыть учебный кейс». Режим SOLO: создать черновик, ввести письмо, дождаться сохранения, принять NDA и отправить. Отзыв терминальный: повторная подача запрещена.

TEAM: создать команду → управление составом → поиск «Демо» → пригласить → открыть заявку. Ожидающее приглашение не мешает черновику, но блокирует отправку. Демонстрация не позволяет подтвердить приглашение за другого человека. Собственное входящее приглашение доступно в «Приглашениях». После отправки состав заблокирован.

Отдельные пункты «Черновики» и «Приглашения» убраны из навигации. «Мои участия» содержит фильтры «Все / Черновики / Активные». Сначала загружаются все страницы существующего API, затем применяется фильтр и локальная пагинация. При изменении total/pageSize или неполном наборе записей показана ошибка вместо неполного результата. Старые /drafts и /invitations перенаправляют в новый раздел. Данные демо находятся в памяти до перезагрузки; между маршрутами сохраняются. Переход со страницы заявки ждёт автосохранения либо требует явного отказа от правок. При 409 текст остаётся в редакторе, тихих повторов нет; загрузка серверной версии требует подтверждения.

## Контракт и безопасность

Адаптер использует существующий apiRequest и cookie-сессию, свежий CSRF перед каждой мутацией. Submit/withdraw используют Idempotency-Key, который сохраняется при явном повторе для той же версии. Все demo ID — UUID. CaseStatus, DTO и ответы сгенерированы из OpenAPI; `python3 scripts/generate_student_types.py --check` контролирует актуальность. Playwright остаётся 1.56.1.

Права и проверки в UI служат обратной связью пользователю; сервер обязан независимо проверять владельца/капитана, членство, курс, срок, размер команды, NDA, версии и идемпотентность. После появления backend нужно проверить эти сценарии с реальными ролями, 401/403/409 и истечением cookie. Семантику значений allowedActions необходимо подтвердить с backend: контракт пока задаёт массив строк без enum; UI действует консервативно.

Отдельного поля portfolioLinks у заявки нет: интерфейс добавляет безопасный http(s)-адрес в coverLetter, учитывая общий лимит 5000 символов. Файлы и рабочее пространство относятся к следующим дням и здесь не реализуются.

Они проверяют CI-сборку, а не конфигурацию Vercel Preview.


## Общий раздел «Команды»

`/student/teams` — подтверждённые команды пользователя; `/student/teams/invitations` — ожидающие приглашения и история решений. Вкладки используют общий UI kit; шапка и глобальная навигация остаются общими с первым днём. Карточка показывает роль, кейс, состав и статус заявки либо «Заявка не создана».

До принятия приглашения показываются только inbox-метаданные без ссылки на внутреннюю команду. GET команды и заявки закрыт до подтверждения членства. После accept команда появляется в «Моих командах», созданная капитаном — сразу, даже без заявки. Список запрашивается заново при открытии вкладки.

Для глобального списка в OpenAPI добавлен read-only `GET /api/v1/me/teams` с MyCaseTeamListResponse: существующий per-case метод не перечисляет созданные команды без заявки во всех кейсах. Это конкретное расширение контракта для серверной команды. Ожидающие приглашения не включаются, чужой состав не раскрывается.

Обычный подтверждённый участник открывает командную заявку только для чтения. Редактирование, отправка и отзыв скрыты по роли даже при ошибочно расширенном allowedActions; demo также запрещает такие команды участнику с 403.

Демоданные обозначены общей плашкой «UI Ready · демонстрационные данные», мобильная шапка использует гамбургер с доступным именем для скринридера.
