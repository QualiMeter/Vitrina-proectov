## Маршруты и демонстрация

- `/demo/student/projects` — кабинет автора, фильтр модерации, изменение разработки.
- `/demo/student/projects/00000000-0000-4000-8000-000000000020/team` — проект автора, кандидат, состав, куратор.
- `/demo/student/projects/00000000-0000-4000-8000-000000000128/apply` — заявка в опубликованный проект другого автора.
- `/demo/student/favorites` — избранные кейсы; можно убрать и снова сохранить учебный кейс.
- `/demo/student/notifications` — личные события и входящие приглашения кейсов.

Демоданные явно обозначены «UI Ready · демонстрационные данные». Все новые ID — UUID. Состояние живёт только в памяти единого DemoProvider: сохраняется при клиентских переходах, сбрасывается при перезагрузке. Переключателя, имитирующего реальную авторизацию, нет; проверки других акторов выполняются отдельными экземплярами адаптера в тестах.

## Ошибки, права и конфликты

Один command за раз. Решения автора отправляются с версией состава, отзыв — с версией заявки, смена разработки — с версией публикации. При 409 решение не повторяется автоматически: доступно явное обновление и новое действие. При 403 дальнейшее действие блокируется до проверки доступа. При сети/500 текст заявки не очищается, можно явно повторить отправку. Если сервер принял запрос, а ответ потерялся, последующий 409 ведёт к чтению текущего состояния без повторной заявки. Навигация и закрытие вкладки защищают неотправленное письмо; используется общий диалог с клавиатурным фокусом и Escape.

В учебной политике одна заявка пользователя на проект сохраняет историю; после отклонения или отзыва повторная подача не предусмотрена. Этот запрет, лимит письма, политика повторного входа после исключения, доступные переходы разработки и правила открытых ролей требуют согласования в BE-24. Подтверждение заявки не закрывает вакансию автоматически и не даёт кандидату прав автора. Автор не может исключить самого себя; передача авторства в этом scope не реализуется.

Уведомления и избранное изолированы по пользователю. Публичная команда содержит только никнейм, роль и опубликованные компетенции; письма, UUID кандидатов и личные контакты туда не попадают. Подтверждение компанией остаётся отдельной доверенной проекцией четвёртого дня.

Для отсутствующих контрактов live-адаптер показывает недоступность и явную ссылку на demo, HTTP-вызовов не выполняет. Ошибки не подменяются учебными данными. Приглашения кейсов на странице уведомлений имеют независимую загрузку и ошибку, поэтому доступны при недоступности новых уведомлений. Публичная выдача только PUBLISHED и все права должны обеспечиваться сервером; клиентские проверки не являются границей безопасности.
