## Просмотр

```bash
cd frontend
npm ci
npm run dev
```

`/demo/student/participations` → «Рабочее пространство» активного кейса.
Прямая ссылка: `/demo/student/cases/00000000-0000-4000-8000-000000000010/workspace`.
Рабочий маршрут: `/student/cases/:caseId/workspace`.

Демо явно помечено «UI Ready · демонстрационные данные». Учебные файлы, комментарии и настройки не подменяют рабочие запросы; перезагрузка сбрасывает демо. Примеры типов PDF/PNG/JPEG и 5 МБ применяются только в демо и не объявляются ограничениями API.

## Правила сдачи

Просрочка не закрывает приём автоматически: isLate приходит в созданной версии с сервера. После ручного закрытия кнопки отправки нет. Обычный участник читает разрешённые материалы и собственную историю, но не отправляет результат. Выбывшему и исключённому форма недоступна; ссылка на разрешённую историю сохраняется в участиях.

Сетевая ошибка сохраняет тело и Idempotency-Key. Повтор отправляет тот же запрос; поля временно заблокированы до получения результата, чтобы не создать другую версию с неоднозначным ключом. После успешной записи история дополняется, форма очищается. Ошибка 409 сохраняет локальные данные, предлагает сравнить последнюю серверную версию и явно подтвердить использование своего текста для следующей версии. Автоматической перезаписи нет. После 403 повторная отправка блокируется, текст остаётся доступным для копирования.

Неотправленное описание, ссылки и файлы защищены единым диалогом при навигации и предупреждением перед закрытием вкладки. Несколько точек используют один navigation blocker.

Файлы загружаются через multipart с CSRF, caseId, checkpointId и applicationId. До READY отправка недоступна; статус можно проверить отдельным запросом. Новый GET `/files/{id}/content` при каждом скачивании снова проверяет текущие права на сервере. Прямые storage URL, prefetch и постоянное хранение приватных файлов отсутствуют; временный blob URL освобождается после передачи браузеру. Ошибки не заменяются демо-файлом.

## Границы контракта

Использованы существующие GET workspace, собственная история и результат отбора, POST версии, POST files, GET метаданных и содержимого файла. OpenAPI и общие зависимости не изменены. Генератор расширен существующими схемами; `--check` продолжает обнаруживать drift.

Не хватает согласованных полей или методов для комментариев компании, результата проверки обычной точки и ограничений файлов на кейс. В рабочем интерфейсе нет вымышленных запросов. Комментарии и пример результата проверки показаны только в демо. Закрытые инструкции и будущие материалы должны отсутствовать в серверном workspace, а не лишь скрываться CSS. Клиент не догружает приватный CaseCheckpoint или общую company-сводку.

## Проверки

```bash
python3 -m pip install -r scripts/requirements-codegen.txt
python3 scripts/generate_student_types.py --check
cd frontend
npm run lint
npm run typecheck
npm run test:coverage
npm run build
npm run test:e2e
```

Unit/integration: роли TEAM/SOLO, NDA, допуск, запрет ранних материалов, закрытие, история, повтор с прежним ключом после network error, явное разрешение 409, сохранение текста после 403, scope файлов, CSRF, защита перехода и отказ скачивания.
E2E: отправка новой просроченной версии, сохранность истории, диалог ухода, роли и закрытие, сеть/409, клавиатура и отсутствие горизонтального скролла на 320/360/375/400/768/1280/1920 px. Свежие снимки сохраняются в артефакте `frontend-playwright-report`, каталог `test-results/screenshots/day3-*`.
