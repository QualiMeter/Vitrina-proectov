# Решения, ожидающие согласования контракта Frontend B

Эти пункты описывают текущие зависимости UI Ready и критерии серверной реализации. Наличие метода в рабочей ветке не означает его утверждения backend-командой.

## Команды и участия

| Область | Текущее поведение | Решение до production |
|---|---|---|
| Глобальный список команд | В ветке предложен GET /api/v1/me/teams и MyCaseTeamListResponse | Подтвердить DTO и пагинацию: команды капитана доступны сразу, даже без заявки; команды участника — только после подтверждения. Ожидающие приглашения остаются в inbox. Уточнить допустимые поля состава, кейса, роли и статуса заявки; частные контакты не возвращать. |
| Фильтры участий | loadAllPages последовательно загружает все страницы, затем фильтрует весь набор и выполняет локальную пагинацию | Это временное решение UI Ready: O(N) по записям и памяти, O(ceil(N/pageSize)) запросов. Согласовать серверные фильтры статуса/активности до пагинации, стабильную сортировку и total после фильтра. Не добавлять неутверждённые query-параметры. |
| Приглашение без публичного имени | Нейтральная подпись «Приглашённый студент»; UUID используется только внутри команды | Если нужно имя, согласовать безопасное поле отображения в DTO приглашения; не подставлять частный профиль и не выполнять произвольные запросы по UUID. |
| Роли и версии | Обычный подтверждённый участник читает заявку, капитан редактирует. Клиент отправляет expectedVersion | Сервер независимо проверяет роль на каждом запросе, возвращает 403 при потере доступа и 409 при конфликте. Согласовать allowedActions и отсутствие внутренних данных до принятия приглашения. |

Автосохранение выполняет один PATCH за раз. Сеть/500 допускает явный повтор с сохранённым текстом. После 409 выполняется отдельное чтение и выбор письма целиком; сохранение локального варианта использует свежую версию, следующие правки снова сохраняются автоматически. При 401/403 текст остаётся доступен для копирования, продолжение требует повторной проверки доступа.

## Публикации

PortfolioWork и StudentInitiativeProject пока отсутствуют в OpenAPI. Рабочий адаптер заблокирован, учебный адаптер включается только явным demo-маршрутом. Новых HTTP-маршрутов для публикаций не добавлено.

До подключения согласовать:

- приватные/публичные DTO, доступ автора, модератора и гостя, expectedVersion и ошибки 401/403/404/409;
- серверную фильтрацию только PUBLISHED до пагинации и подсчёта total; черновики и замечания модерации не должны попадать в публичный HTTP-ответ;
- подтверждение компанией только через доверенную серверную проекцию, без пользовательского поля «подтверждено»;
- поведение предыдущей опубликованной версии при редактировании и матрицу полей, требующих повторной модерации;
- upload scope, серверную проверку содержимого и преобразование изображений, лимиты, права на чтение/привязку медиа, staged-загрузки и удаление потерянных вложений.

PNG/JPEG/WebP, PDF/ZIP/TXT и 10 МБ — только ограничения учебного адаптера. Они не заявляются защитой production. Клиент отклоняет известную приватную форму DTO в публичных читателях, но это не заменяет серверное ограничение публикации и доступа.

Конфликт публикации разрешается по каждому полю. Ссылки, материалы, технологии, интересы и вакансии выбираются целыми списками; автоматического слияния элементов нет. Применение выбора обновляет форму и expectedVersion, сохранение выполняется отдельным действием. Проверка обязательных полей перед модерацией одинакова в списке и редакторе.
