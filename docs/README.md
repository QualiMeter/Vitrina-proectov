# Документация API «Витрина ИТ-проектов»

**Версия проекта:** `0.1.5-draft` · **Дата:** 30.10.2026 · **Не реализовано в backend**.

## Навигация

- [`api/openapi.yaml`](api/openapi.yaml) — единый HTTP-контракт OpenAPI 3.1 для P0-сценария, включая личный кабинет студента.
- [`api/REQUEST-EXAMPLES.md`](api/REQUEST-EXAMPLES.md) — примеры запросов frontend.
- [`api/REVIEW-CHECKLIST.md`](api/REVIEW-CHECKLIST.md) — проверки перед утверждением.
- [`../scripts/validate_openapi.py`](../scripts/validate_openapi.py) — независимая проверка YAML, OAS 3.1 и правил API, запускается в GitHub Actions.
- [`api/PLAN-V2.1-ALIGNMENT.md`](api/PLAN-V2.1-ALIGNMENT.md) — сверка с пятидневным планом v2.1: что добавлено и что требует решения TL.
- [`architecture/cases-teams-applications.md`](architecture/cases-teams-applications.md) — кейсы, команды и заявки.
- [`architecture/execution-submissions-files.md`](architecture/execution-submissions-files.md) — этапы, сдачи, отбор, приватные файлы и NDA.
- [`architecture/case-evaluation-results.md`](architecture/case-evaluation-results.md) — оценивание, отзывы, победители и публикация.
- [`decisions/001-auth-and-permissions.md`](decisions/001-auth-and-permissions.md) — согласованные решения и неутверждённые проектные предположения.
- [`ci-cd.md`](ci-cd.md) — существующая документация CI/frontend.

## Ответственные

- **Backend** — владелец HTTP-контракта и бизнес-валидации.
- **Тимлид** — утверждение бизнес-решений, приоритета и изменения DTO.
- **FE-A/B/C** — потребители одной схемы; не придумывают отдельные HTTP-контракты.
- **DevOps** — согласование конфигурации окружений, файлового хранилища и проверок.

## Статус и ограничения

- Контракт содержит **94 операции, 150 схем**. Это **не** 94 реализованных эндпоинта.
- Покрыт **основной корпоративный P0-сценарий**: регистрация → компания → кейс → заявка/команда → выполнение/отбор → результаты.
- Для P0 добавлены: личный/публичный профиль студента, «Мои участия» и справочники read-only. Владелец backend подтверждает DTO и публичность полей до реализации.
- Вне этой версии: отдельные модели портфолио, студенческих инициатив, закрытых продуктовых проектов, кадрового поиска, полной аналитики, администрирования и уведомлений (P1 по пятидневному плану). Они **не отменяются**, но требуют отдельного расширения единого `openapi.yaml`.
- **Согласовано тимлидом:** ручной SOLO-отбор по принципу TEAM; NDA при подаче подписывает капитан TEAM или сам SOLO; состав команды изменяется до submit и замораживается после; после REJECTED/WITHDRAWN повторная подача запрещена; публично видны никнейм/аватар/достижения, компаниям дополнительно ФИО/группа/курс; приглашение компании 7 дней.
- **Ещё требуют технического/предметного review:** права представителей компаний на учебные данные, правила никнеймов и изображения, матрица прав капитанства после подачи, параметры файлов, категории P1, формат публикации итогов.
- Для независимой OpenAPI-валидации добавлены GitHub Actions и валидатор OAS 3.1. Статус запуска проверяется в PR; серверные интеграционные тесты ASP.NET Core пока недоступны.

**Правило:** merge проектной документации в `main` означает доступность единого baseline, **не** принятие всех DTO backend-разработчиком и не готовность API. При изменении бизнес-логики требуется TL; backend может дополнять контракт отдельными PR с проверками. На frontend mock можно работать со статусом **UI Ready**; **Done (API)** — только по реальным интеграционным проверкам.
